# SYNC-2

**SYNC-2 (new, v13.30) — the sync publishes neither what the allowlist blocks nor what it includes.** Measured against the published tree: 250 files shipped, but `messages/**/*.json` (5 files) and `supabase/migrations/**/*.sql` (218 files) are **entirely absent** although both are explicit `patterns` entries, and `src/app/[locale]/products/ars-api` and `.../pricing` are absent too. So the showcase is a non-runnable subset while the README on its front page promises "anyone can audit, run, and contribute" — no translations and no schema means nobody can run it. The README also links `./docs/KVKK.md`, `./docs/ARCHITECTURE.md` and `./docs/SECURITY.md`, all three of which `**/docs/**` blocks, so the storefront's first screen carries three broken links. The likely mechanism is the PII scan rejecting migration files that contain seeded third-party email addresses (`rollback_fake_outreach_seed.sql` among them) with the rejection not surfacing in the audit log, which would mean failures are being swallowed rather than reported — that is the part worth fixing first, because a silent filter is how PII-1 got shipped. **Acceptance:** the sync fails loudly and names every file it dropped and why; `messages/**` and `supabase/migrations/**` either publish or are removed from the allowlist so the manifest stops lying; README links resolve inside the public tree; and a dry run's file manifest is reviewed before any further live sync. `scripts/**` is Implementer-owned (G-6)
