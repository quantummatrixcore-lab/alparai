## v13.6 — Repository language fixed to English (2026-08-10)

_First archive section written under Rule 13. Preceding sections stay Turkish and are frozen._

### 0. Why this round is legitimate

Not an Architect-initiated round: the Founder issued a binding language decision. No halt-rule check applies to a direct governance instruction.

### 1. The decision

Everything committed to the repository is written in English — documentation, `README`, commit messages, PR text, code identifiers, script output, CI job names, issue templates. The only exception is the chat reply to the Founder, which stays Turkish under Rule 12. Chat output never enters the repository; everything that does is English.

### 2. Why it is a data-integrity decision, not a stylistic one

v13.5 measured **91 mojibake occurrences** in `messages/en.json` — UTF-8 content that had been read back as Windows-1252 and re-saved, turning an em-dash into `â€"`. Turkish prose is dense in non-ASCII characters (`ı ğ ş ç ö ü İ Ğ Ş Ç Ö Ü`), so every encoding round-trip through a mis-configured tool is an opportunity for the same corruption class. Reducing non-ASCII surface in committed text reduces the number of ways that failure can recur.

The second reason is distribution. `README.md` measured **66 of 211 lines Turkish (31%)** and is the public repository's front page. An HN/Reddit launch sends its highest-intent traffic there first.

### 3. Rule 10 — the inventory that justified this round was itself defective

The first measurement used `grep -rl '[ığşçöüİĞŞÇÖÜ]'`. In a byte-oriented locale, that character class is treated as a set of **bytes**, not characters. `İ` (U+0130) encodes as `C4 B0`; `°` (U+00B0) encodes as `C2 B0`. The shared `B0` byte makes `grep` report `360°` as Turkish text.

Consequence: the reported "120 files under `src/` contain Turkish" was inflated by false positives. Spot-checking confirmed it — three sampled files matched on `360°`, `Atatürk` (a genuine but harmless placeholder), and section headers.

The enforcer therefore does its own detection in Node with a Unicode-aware regex (`/[ığşçöüİĞŞÇÖÜ]/u`) rather than shelling out to `grep`. Measured with the correct method, **221 tracked files** across the repository still contain Turkish and are grandfathered.

**Lesson, same shape as v13.5's proxy finding:** two rounds in a row, the defect was in the measuring instrument rather than the thing measured. When a number looks large, verify the tool before acting on the number.

### 4. Three tiers (Founder decisions)

**Tier A — before launch.** Public-facing surfaces: `README.md`, `CONTRIBUTING.md`, root `SECURITY.md`, `CODE_OF_CONDUCT.md`, `.github/ISSUE_TEMPLATE/**`. These ship together with the mojibake cleanup (BG) because both are storefront-quality defects on the same surface.

**Tier B — after launch.** Internal documentation, ordered by read frequency rather than file size: `docs/MASTER_PLAN.md` (109/215 Turkish), `docs/ROADMAP.md` (177/355), `AGENTS.md` (24/254), `CLAUDE.md` (3/87), then `ARCHITECTURE.md`, `API.md`, `AUTOPILOT.md`, `MAX_OTONOMATION.md`, `UI-UX-AUDIT.md`. When translating `docs/MASTER_PLAN.md`, the `FOUNDER_BACKLOG_START/END` markers and the five-column table contract must be preserved — `parseMasterPlan()` and the `/admin/strategy` panels read that schema. Translation is not a schema change.

**Tier C — frozen, never translated.** `docs/MASTER_PLAN_ARCHIVE.md` (5,610 lines), `docs/ARCHIVE/**` (3,615 lines), `docs/plan/v12.*.md` (~4,000 lines), and the pre-v13.6 sections of this file. These are the evidence base that Rule 10 depends on. Translating them would rewrite the evidence and inject mistranslation risk into the historical record — the opposite of what an evidence rule is for. Each group receives an English freeze notice instead.

### 5. Product content is out of scope

`messages/**` is the product's multilingual interface and stays in its target languages. `Basın/**` is a Turkish press kit written for Turkish journalists — content, not documentation. Both are permanent exemptions in the enforcer.

Bilingual content structures under `src/` (`src/lib/constants/press-releases.ts`, `src/content/blog-posts.ts` and similar, carrying `tr:` / `title_tr:` fields) are product data too. They are left in the baseline rather than exempted outright, because the same scan also catches a genuinely different problem: hardcoded Turkish UI strings in admin components, which v12.110 already found once (`master-plan-deps-graph.tsx`, #131). Separating the two is a diagnosis task (BM), not something to assume now.

### 6. The enforcer is a ratchet, and that is deliberate

Doctrine #047 requires every binding rule to ship with an executable enforcer. A blanket ban would have turned CI red the moment the rule landed, and G-6's own condition ("a failing verification means revert, not 'fix it next commit'") would then have required reverting the rule itself.

So `scripts/check-repo-language.mjs` compares against `.repo-language-baseline`, a generated list of the files that already contain Turkish. Those are grandfathered. Any file outside both the baseline and the permanent exemptions that contains Turkish characters fails CI. Baseline entries may only be **removed** as files are translated, never added — the list can shrink but never grow. The script also reports entries that are now clean, so the list stays honest as translation proceeds.

**Verification performed before commit (G-6 requirement):** the check passes on the current tree (221 files grandfathered), and a negative test — removing `docs/MASTER_PLAN.md` from the baseline — fails with exit 1 and names the file and its 97 offending lines.

### 7. Scope note

`package.json` did not receive a script alias for the new check; CI invokes `node scripts/check-repo-language.mjs` directly. Reason: G-6 limits Architect edits in `package.json` to dependency-security fields, and a convenience alias is not one.

### 8. Enforcer specification (verified source, for the Implementer to land verbatim)

Written and tested in this session, then **refused at commit time by `.husky/pre-commit`** because `scripts/` and repo-root data files sit outside the Architect's writable paths. The refusal is correct: G-6 enumerates the enforcement layer as `.github/workflows/**`, `.husky/**`, `playwright.config.ts` and dependency-security fields in `package.json`. `scripts/` is not on that list, and quietly widening the guard to admit one's own code is the precise failure mode G-6a was written to prevent. So the work is handed over as a specification instead of being forced through.

**Verification already performed (do not re-derive, just confirm after landing):** on the tree at commit `1c5145ca` the check exits 0 with 221 files grandfathered; removing `docs/MASTER_PLAN.md` from the baseline makes it exit 1 and report 97 offending lines.

```javascript
const ROOT = process.cwd();
const BASELINE_PATH = join(ROOT, ".repo-language-baseline");

const TURKISH_CHARS = /[ığşçöüİĞŞÇÖÜ]/u;

const SCANNED_EXTENSIONS = [".md", ".ts", ".tsx", ".mjs", ".js", ".yml", ".yaml"];

const PERMANENT_EXEMPTIONS = [
  "messages/",
  "Basın/",
  "docs/ARCHIVE/",
  "docs/MASTER_PLAN_ARCHIVE.md",
  "docs/plan/v12",
  "scripts/check-repo-language.mjs",
  ".repo-language-baseline",
];

function isExempt(path) {
  return PERMANENT_EXEMPTIONS.some((prefix) => path.startsWith(prefix));
}

function isScanned(path) {
  return SCANNED_EXTENSIONS.some((ext) => path.endsWith(ext));
}

function trackedFiles() {
  return execFileSync("git", ["ls-files", "-z"], { encoding: "utf8", maxBuffer: 64 * 1024 * 1024 })
    .split("\0")
    .filter(Boolean);
}

function turkishLineCount(path) {
  let content;
  try {
    content = readFileSync(join(ROOT, path), "utf8");
  } catch {
    return 0;
  }
  let count = 0;
  for (const line of content.split("\n")) {
    if (TURKISH_CHARS.test(line)) count += 1;
  }
  return count;
}

function loadBaseline() {
  if (!existsSync(BASELINE_PATH)) return new Set();
  return new Set(
    readFileSync(BASELINE_PATH, "utf8")
      .split("\n")
      .map((line) => line.trim())
      .filter((line) => line && !line.startsWith("#")),
  );
}

function scan() {
  const offenders = [];
  for (const path of trackedFiles()) {
    if (!isScanned(path) || isExempt(path)) continue;
    const count = turkishLineCount(path);
    if (count > 0) offenders.push({ path, count });
  }
  return offenders.sort((a, b) => b.count - a.count);
}

if (process.argv.includes("--write-baseline")) {
  const offenders = scan();
  const header = [
    "# Repo language baseline — English-only policy (Rule 13).",
    "# Files listed here still contain Turkish text and are grandfathered.",
    "# This list is a RATCHET: entries may be removed once a file is translated,",
    "# and must never be added. A new file with Turkish text fails CI.",
    "# Permanently exempt (not listed): messages/**, Basın/**, docs/ARCHIVE/**,",
    "# docs/MASTER_PLAN_ARCHIVE.md, docs/plan/v12*.",
    "",
  ].join("\n");
  process.stdout.write(header + offenders.map((o) => o.path).join("\n") + "\n");
  process.exit(0);
}

const baseline = loadBaseline();
const offenders = scan();
const unlisted = offenders.filter((o) => !baseline.has(o.path));

if (unlisted.length > 0) {
  console.error("Repo language check FAILED — Turkish text in files not covered by the baseline.");
  console.error("Rule 13: everything committed to this repository is written in English.");
  console.error("");
  for (const { path, count } of unlisted) {
    console.error(`  ${path} — ${count} line(s) with Turkish characters`);
  }
  console.error("");
  console.error("Translate the file, or if it is product content, add it to PERMANENT_EXEMPTIONS.");
  console.error("Do NOT add it to .repo-language-baseline — that list only shrinks.");
  process.exit(1);
}

const stale = [...baseline].filter((path) => !offenders.some((o) => o.path === path));
const remaining = offenders.length;

console.log(
  `Repo language check passed. ${remaining} file(s) still grandfathered by the baseline.`,
);
if (stale.length > 0) {
  console.log("");
  console.log(`${stale.length} baseline entry/entries are now clean and can be removed:`);
  for (const path of stale.slice(0, 20)) console.log(`  ${path}`);
}
```

**Design notes the Implementer should not "simplify" away.** The ratchet is the whole point: a blanket ban would have turned CI red on adoption day, and G-6's own condition ("a failing verification means revert") would then have forced reverting the rule itself. Detection runs in Node with a Unicode-aware regex rather than shelling out to `grep`, because byte-wise matching reports `360°` as Turkish (`U+0130` and `U+00B0` share a trailing byte) — that defect inflated this policy's first inventory. `Basın/` and `messages/` are permanent exemptions because they are product content in their target language, not documentation. ## v13.63 — A valid CSP that disabled the application (2026-08-19)

**Outage.** The Founder reported `/en` with no hero and no data. Every server-side signal read
healthy: HTTP 200, 627,785 characters, full navigation, hero copy, five real live-feed incidents,
the provider leaderboard, zero `MISSING_MESSAGE` or `IntlError`, and an empty DeHost runtime-error
table. The failure was entirely in the browser and the cause was one line.

**Cause.** Commit `d8bd006d` removed `'unsafe-inline' 'unsafe-eval'` from `script-src` at
`next.config.mjs:11` as a hardening measure, without adding a nonce mechanism. Measured on the live
page: 25 inline `<script>` elements, **0** carrying a nonce, **20** of them the `self.__next_f` RSC
flight payload, which itself records `"nonce":"$undefined"`. React streams `<Suspense>` content to
the **end of the document** and relocates it with inline `$RC()` calls — 3 pending markers and 3
`$RC(` calls were present. With those scripts blocked, nothing hydrated and nothing moved:
`<footer>` sits at 31.0% of the script-stripped body and the sole `<h1>` at 41.3%, i.e. the hero
renders **below the footer** while its skeleton freezes at the top. Verified still present on the
remote via `git show origin/master:next.config.mjs`.

**The architectural point.** Inline scripts are not an incidental convenience in this framework;
they are the transport for both hydration and Suspense relocation. A CSP that forbids them without
supplying a nonce does not harden the application — it disables it, while remaining a perfectly
valid CSP.

**Why no gate caught it.** A response header is not a build artifact, so `pnpm build` was green and
had no way not to be; a directive string has no type or lint surface; no unit test asserts response
headers; Playwright's presence assertions pass against server-rendered HTML and cannot distinguish a
hydrated application from an inert document; and DeHost's error table is server-side while CSP
violations are raised by the browser. The systemic finding: **no layer of the test pyramid asserts
that the application hydrated.** Every gate measured the server, and the server was never wrong.

Two earlier commits — `65b7c09c` ("prevent infinite loading skeleton crash") and `8fbe42b1`
("remove root loading and resolve hydration mismatch causing infinite skeletons") — treated the
frozen skeletons as a data or layout defect and patched around them. When a fix targets a symptom
and the symptom returns, the next step is to falsify the assumed mechanism, not to patch harder.

**Decision and full reasoning:** `docs/adr/0013-csp-streaming-hydration.md`. Restore the known-good
directive; the per-request nonce in middleware is the correct end state but forces dynamic rendering
on every route across five locales, which is not a change to make during a live outage.
`'strict-dynamic'` was considered and does not reach inline scripts.

**Implementer work:**

- `CSP-1` — restore `'unsafe-inline' 'unsafe-eval'` at `next.config.mjs:11`. ✅ **Complete**
  (commit `aa8a67ed`, deployed to production 2026-08-19 21:27 UTC, live on alparai.com)
- `CSP-2` — add `scripts/check-csp-hydration.mjs` per ADR-013 §Enforcer: fail when `script-src`
  carries neither `'unsafe-inline'` nor a `nonce-` placeholder while `src/middleware.ts` sets no
  per-request nonce. Wire as a step in `.github/workflows/ci.yml`.
- `CSP-3` — a Playwright assertion that no unresolved streaming boundary survives load. Presence
  assertions must never again be read as evidence of hydration.
- `CSP-4` — scope and measure the nonce migration, including the static-rendering cost.

**Correction on the record.** This session reported a `clientKeys` allowlist regression in
`src/app/[locale]/layout.tsx`. It does not exist — `16102f28` had already removed it, and the branch
shows `messages={messages}` at line 74. The finding came from a stale local working copy. The

in an investor document or in a report as evidence of what has happened. Where a real-world outcome
matters the schema must carry a field for that outcome and its date, and the absence of that field is
itself the defect to file.

## v13.68 — Prioritisation, funding, distribution and the admin panel, assessed together (2026-08-20)

The Founder asked five questions at once — how to prioritise, what to do about social accounts,
whether we are ready to seek investment and where to apply, what happened to the mail we sent, and

substance of this entry.

### The prioritisation axis changes when the goal is funding

This board has always ordered work by defect severity. For a company about to seek investment that is
the wrong axis, and keeping it would produce a sequence that looks busy and raises nothing. The right
axis is **what gates everything downstream**, and there are three gates in a fixed order.

**Gate 1 — nothing published is false.** Diligence and legal exposure both terminate here, and this is
the only gate where a single artifact can end the conversation outright: a fabricated incident naming
a real company, found by a reviewer, is not a bug report, it is a verdict on the project's thesis.

**Gate 2 — the build is green.** Every "done" on this board is unverifiable while `master` is red,
which means the board itself stops being evidence. A technical reviewer runs the build; it is usually
the first thing they do and the cheapest signal they take.

**Gate 3 — the product shows real data.** An accountability registry with no incidents in it is a
thesis, not a product. Until the corpus is loaded and attributed, there is nothing for a visitor,
a journalist or an investor to look at.

Outreach — press, social, investors — comes **after** all three, and not because outreach is less
important. It is because **investor attention is non-renewable per firm.** A warm intro spent on a
product with an empty leaderboard and a red build converts into a permanent no at that firm; the same
intro three weeks later, with a loaded corpus and a green build, is a live conversation. There is no
version of this where going early is cheap.

### The admin panel: the menu is healthy, six pages are not, and three of those are what the deck sells

Measured 2026-08-20. All **30** sidebar entries resolve — there are **no dead links**, which is better
than expected. Around **40** routes run a real query. Four pages are orphans, reachable by URL but
absent from the menu (`cockpit`, `cron-health`, `quotas`, `velocity`).

**Six pages are not live, and the three that matter are the three the pitch deck leans on.**
`analytics-hub/k-benchmark` displays **ten hardcoded model scores** (`page.tsx:43-127`) — and
K-BENCHMARK is sold in the deck as half the product, so the panel that would demonstrate it shows
invented numbers. `api-keys` reports that "key generation is temporarily disabled for maintenance"
(`page.tsx:31`) — and API key issuance is the monetisation path v13.64 identified, currently switched
off. `legal-tracker` renders **five hardcoded notifications** with dates fixed at "13 Aug 2026"
(`page.tsx:31-72`), sitting beside a real legal register this project maintains against a named
vendor. The remaining three: `strategy/master-plan` carries a dead `fetch("/api/placeholder")` behind

## v13.86 — The reporting form, and a transcription endpoint that invents evidence (2026-08-21)

The Founder reported four things about filing an incident: it demands both a short and a long
description, the model list is out of date, voice recording does not work, and the whole thing is
harder than it should be. All four check out in the code, and the third turned out to be something
other than "does not work".

**`src/app/api/ai/transcribe/route.ts` fabricates the transcript when it fails.** If
`OPENROUTER_API_KEY` is absent, or the model call fails, or the response is unusable, the route does
not return an error. It returns HTTP 200 with a hardcoded Turkish sentence meaning:

> "[Voice recording successfully transcribed: the AI model produced an unexpected response and
> violated the system security protocol.]"

The user speaks a description of a real incident. The system discards it, **states that transcription
succeeded**, and substitutes an invented sentence that is itself an accusation against an AI model —
into the description field of an incident report, attributed to whichever provider they selected.

**This is the most serious fabrication found on this board.** The earlier ones invented metrics about
ourselves: a transparency score, a K-benchmark table, a readiness percentage. All bad, all removed.
This one invents **evidence**, out of a user's own words, on the single surface where the project's
value rests entirely on the record being real. And it does so while reporting success, which is why it
has read as "voice doesn't work" rather than as what it is.
[VOICE-1](plan/items/VOICE-1.md), P0. The correction is to delete the fallback: a failed transcription
returns a non-2xx with a reason. A user told the recording failed can type instead; a user told it
succeeded has no reason to check.

**The other three are one problem — the form asks too much of the person least able to give it.**
`incident-form.tsx:718-737` requires **both** a title of up to 200 characters and a description of up
to 5,000, so someone who has just experienced something must compose a headline and an essay before
the form will accept them. The model list is the `ai_models` table — the same one `LB-1` is purging of
fabricated entries, never refreshed with the models people actually use — so a reporter looks for
their model, does not find it, and either picks something wrong or leaves. And voice, the alternative
for anyone who cannot type, additionally requires a signed-in session (`transcribe/route.ts:7-10`),
which under `AUTH-1` puts the double sign-in between a whistleblower and their report.
[INTAKE-1](plan/items/INTAKE-1.md).

**The principle, because it decides the next twenty design questions:** the reporter is doing us a
favour. Every mandatory field asserts that we need something more than we need their report, and the
form currently makes that assertion four times before a word is typed. One required free-text field
files a report. An unlisted model is metadata a moderator resolves later and must never block
submission. A broken alternative path is worse than none, because it spends the single attempt of
exactly the person who could not use the main one.

**Measure before redesigning further.** Instrument form-opened and submitted, so the next change aims
at where people actually stop. Guessing at friction is how forms acquire fields in the first place.

## v13.85 — The double sign-in, located (2026-08-21)

The Founder has reported a double authentication on login many times and it has never been fixed. An
earlier session in this conversation looked at it and set it aside — which, under the invariant
written two entries ago, is precisely the kind of "found nothing" that does not count as a finding.
Looked at properly, the mechanism is in the code and is not subtle.

**`auth-buttons.tsx:112-126`.** The Google Identity Services button authenticates the user and returns
a credential. The credential goes to the `signInWithGoogleIdToken` server action. If that action
returns anything other than success, the next line calls `fallbackOAuthRedirect()` — which is
`signInWithOAuth`, the full redirect to Google's consent screen. **A user who has just authenticated
with Google is sent to Google again.** The same call sits in the no-credential branch.

If the server-side exchange fails for a configuration reason — the client ID registered in DeHost's
Google provider not matching `NEXT_PUBLIC_GOOGLE_CLIENT_ID`, or ID-token sign-in not enabled — this
fires on **every** login. That fits a defect reported repeatedly over months and never reproduced as
broken: the second flow succeeds, the user does get in, and the only signal is a toast that flashes
during a redirect they were expecting anyway. **A defect that always recovers is a defect nobody can
file.** [AUTH-1](plan/items/AUTH-1.md), P0.

**One diagnosis was checked and rejected.** An automated review named the nonce handling as the root
cause — hashed nonce to Google, raw nonce to DeHost. That asymmetry is DeHost's **documented**
pattern: Google embeds the hash in the token, DeHost hashes the raw value to compare. Relaying it
would have sent the Implementer to rewrite working code. Also positively ruled out, each with its
line: the middleware excludes `auth/callback` from its matcher, the sign-in page already redirects an
authenticated visitor away, and the callback route writes its cookies onto the response it returns.

**The first action is measurement, not a fix.** `res.error` already carries the reason and is thrown
away into a toast. Logging it server-side on one real login answers whether the exchange fails always
or occasionally, and that answer decides which fix is right. Changing code before that would be
guessing at a bug that has survived this long precisely because everyone guessed.

**The design lesson, which outlives this bug:** a silent automatic fallback to a second identity
provider round-trip is not resilience, it is a decision made on the user's behalf that their first
authentication did not count — and it converts a hard failure that would have been fixed in a day into
a soft one that survives for months. Fall back automatically only when the user cancelled; on a server
rejection, show the error and let them press the button.

Separately, two callback routes exist with `safeNextPath` and `detectLocale` duplicated verbatim;
OAuth uses one and email links the other. Consolidation is filed with the item, not as part of the fix.

## v13.83 — Recurrence analysis across the full archive, and three mechanisms that answer it (2026-08-21)

The Founder asked for the whole plan, archives included, to be analysed for defects that keep
repeating, and for the plan to be changed so they stop. Two forensic sweeps read
`docs/MASTER_PLAN_ARCHIVE.md` (5,610 lines), `docs/plan/v12.*.md` and `docs/plan/v13.*.md` in full —
roughly 13,400 lines spanning v11.54 to v13.82 — and returned **ten recurring families with 59+ dated
occurrences**. Marker counts across the same corpus: "fabricat*" **91**, "regress*" **48**, "stale"
**40**, "mojibake" **34**, `ARCHITECT=1` **22**, "retract*" **8**, `--no-verify` **5**.

What follows is not the list. The list is evidence; these are the four findings that explain it, and
what has been built in response.

### Finding 1 — The deepest pattern is measuring with the wrong instrument and reporting it as reality

Three consecutive versions each corrected the previous one's measurement error, not its judgement.
v13.5 reported "Cloudflare WAF blocks three routes" — the 403 came from the agent's own proxy. v13.6
reported "120 files contain Turkish" — a byte-wise grep matching characters that share bytes with
non-Turkish ones. v13.7 reported "the commit is not on origin" — a stale local ref that had never been
fetched. Each drove doctrine. Each was wrong about the world and right about the tool.

**It happened twice more in this session, in this file, by the Architect.** v13.71 recorded the
`public_statement` RLS policy as missing; it existed, and a delegated search had not found it. v13.66
recorded `.i18n-key-coverage-baseline` as non-existent; it had been committed the previous day
(`9c35516b`, 2026-08-19), so an external auditor was marked wrong about something it had right.

Both were **absence claims**, and absence is precisely what a delegated grep is worst at establishing:
a search that finds nothing is indistinguishable from a search that looked in the wrong place. This
single class produced more false statements in this plan than fabrication ever did.

### Finding 2 — Rules without enforcers are not weak rules, they are decorations

The v12 sweep found `G-5a` — every direct execution must be logged as a one-line exception in this
file. **It has never been logged once.** Not once in seventy versions. Any rule that asks an agent to
volunteer a record of its own shortcut collects nothing, and its zero entries then read as compliance.

Doctrine #047 already requires an enforcer per binding rule, and three specified enforcers were never
landed because `scripts/` sat outside the Architect's writable paths. But the sharper gap is one this
session measured directly: **`scripts/check-model-catalog.mjs` exists and is invoked by nothing** — no
workflow, no hook, no package script. It is the enforcer written to stop fabricated model names
returning, and it has never run. Doctrine #047 says an enforcer must ship. It never said it must be
wired, so one wasn't.

### Finding 3 — Closure has two sources of truth, and they disagree in both directions

The archive records phantom closures (prose says complete, the table says pending) and the inverse
(work verified done, the row never updated). This session produced one of each within hours: three P0
rows carried as open after the work was finished, and `ADMIN-6` ticked on a commit that could not have
closed it. **`CONST-2` is the quiet case** — its fabricated-quotes page is gone from disk, yet it was
cited as open repeatedly in this session, including by the Architect, because nothing ever recorded
its resolution.

### Finding 4 — Specifications drift out of the board and nobody notices

Measured: **106 item files, 35 referenced in the current plan, 12 carrying a closure record — and 57
that are neither.** More than half the specification corpus is in a state where nobody can act on it
and nobody can tell whether the work happened. Of the 12 that reached closure, 5 contain reopen or
regression language.

### What was built, rather than written

**`scripts/check-spec-drift.mjs`** — fails when an item file is neither referenced in this plan nor
carries a `## Closed` section. Ratcheted through `.spec-drift-baseline` at the 57 found today; entries
may only be removed. Answers Finding 4.

**`scripts/check-enforcers-wired.mjs`** — fails when a `scripts/check-*.mjs` is invoked by no workflow,
hook or package script. It caught `check-model-catalog.mjs` on its first run, which is now wired into
`ci.yml`. Answers Finding 2's sharper half.

Both are in the Master Plan Guard workflow alongside `check-plan-claims.mjs`, which already answers
Finding 3 by requiring a `closed-by:<sha>@<branch>` citation on every tick.

**Finding 1 has no automated enforcer, and pretending otherwise would repeat Finding 2.** No script can
tell whether a "does not exist" was established by looking in the right place. It becomes Rule 14 in
`CLAUDE.md` — an absence claim must cite the exact command and quote its output, and may not rest on a
delegated search — and it is enforced by review, which is a weaker mechanism honestly labelled rather
than a strong one falsely claimed.

### The chain worth remembering

The v12 sweep traced the project's only real-world incident to these patterns in sequence: an Architect
decision that the repository must stay private was written on a branch that was never merged; the
Implementer, reading `master`, saw the older instruction; and executed it correctly, making the
repository public. No agent misbehaved at any step. **Unmerged doctrine is not bookkeeping debt — it
is an instruction that is still live and now wrong**, which is why `G-8`'s sync is mandatory and why
this session merges to `master` after every entry.
