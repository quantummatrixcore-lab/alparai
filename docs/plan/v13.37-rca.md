A self-correction rate this high is not a sign of sloppiness. It is a sign that corrections are happening _at audit time_ rather than _at write time_ — months after the claim entered the record, and only when a human or an Architect session happened to look.

## 2. Root cause

Every failure in this project's history, mine and the Implementer's alike, reduces to one mechanism:

> **A claim was accepted as evidence because nothing executable could contradict it.**

The project has 8 binding rules and 3 doctrines, and 3 of its 13 enforcers are wired to nothing. Where an enforcer exists, the rule holds — `.husky/pre-commit` blocked this session's own `MASTER_PLAN.md` commits twice today and was right both times; `check-i18n.mjs` caught the parity break; `check-repo-language.mjs` caught the UTF-16 baseline corruption. Where only prose exists, the rule is violated routinely and the violation surfaces later, by hand.

This is not a discipline problem. It is a design problem, and it has three distinct sub-mechanisms.

### 2a. Checks that verify shape instead of substance

The dominant failure mode, and the most dangerous, because it produces _false_ confidence rather than none:

- `check-masterplan-consistency.mjs` required `parts[1]` to be a bare integer. Every row began `| SEC |`, `| PII |`, `| SYNC |`. It parsed **0 of 50 rows** and reported "passed" — for months. It was green _because_ it was empty.
- `.github/workflows/test-runner.yml` echoed and exited 0. A check named "test-runner" that ran no test told every reader tests had run. Deleted this session.
- `scripts/deploy-gate.mjs` gated production on "is the branch master and did code change" — never on whether anything passed. Rewritten this session.
- The v13.34 migration script reported "loss audit passed" while corrupting 11 rows, because the audit compared what the script produced against what the script had parsed — both sides of the comparison shared the same defect.

The pattern: **a check that cannot fail on real input is worse than no check.** Absence of a check is visible. A green check that measures nothing is invisible, and it actively suppresses the manual review that would have caught the defect.

### 2b. Goodhart — measuring the cheap proxy

`check-master-plan-length.mjs` counts lines. Cost per line was unbounded, so the file reached **334 KB while honouring a 400-line cap**, and when it got tight the cap was raised to 600. The metric was never the quantity anyone cared about; it was the quantity that was easy to count. The file grew sideways for months in full compliance.

This same section is subject to it: writing this analysis into `MASTER_PLAN.md` would have pushed it past the cap. The correct response is the one taken — move the detail out and keep the board short — not raise the cap again.

### 2c. Doctrine as prose does not bind delegated agents

Measured this session: **three of three** subagents read `CLAUDE.md`, encountered the Architect/Implementer separation, and each disregarded it to perform the `src/**` edits their assigned task required. Two independently flagged the doctrine itself as suspicious — one called it "role-play", another advised checking where the content came from, observing that a document instructing an agent not to edit the files a legitimate task requires is worth a second look.

Their conduct was correct in every case: the tasks were narrowly scoped with paths enumerated, which is the exact condition G-5's own delegation threshold says direct execution is right for. All three disclosed what they had done. **The gap is in enforcement design, not agent conduct.**

The generalisable lesson: agents are trained to distrust instructions that arrive as ambient context and conflict with an operator's explicit task — which is correct behaviour, and the same behaviour that protects against prompt injection. Rules stated with their rationale survive that filter. Bare prohibitions do not. A rule intended to bind a delegated agent must therefore either ship with an executable enforcer, or be restated in the task prompt with its reasoning.

## 4. Controls

Ordered by leverage. Each is executable or it does not count.

**C-1 — Every enforcer must have a negative test.** A meta-check runs each `scripts/check-*.mjs` against a known-bad fixture and requires exit 1. This is the single highest-leverage control in this document: it kills the entire 2a class, including the specific defects that let a consistency check pass on zero rows and a test-runner pass on zero tests. Any check that cannot be made to fail is deleted, not kept.

**C-2 — Wire or delete.** The 3 enforcers wired to nothing are either added to `ci.yml` or removed. An enforcer that no pipeline invokes is documentation wearing a script's clothes.

**C-3 — Closure citations verified mechanically.** Extend `check-closure-evidence.mjs`: every `closed-by:<sha>` must resolve via `git cat-file -e`, and the cited commit must touch at least one path named in the item. Non-SHA sentinels (`latest`, `pending-push`, `verified`, `legacy`) fail. This turns G-7 from a convention into a gate, and would have caught the SEC-1 misattribution at write time.

**C-4 — Rules ship with enforcers or are labelled unenforced.** Three states only: enforced (name the script), unenforced-by-design (say so in the rule text), or deleted. No rule may sit in the ambiguous fourth state where readers assume enforcement that does not exist. Applies to G-6 immediately: it has no Architect-side enforcer and must say so until it does.

**C-5 — Disjoint write-ownership for parallel agents.** No two concurrently running agents may be assigned the same file. The dispatcher assigns path sets; agents that need a shared file queue behind each other. This session lost a fix to exactly this and caught it only by chance.

**C-6 — Scope is fixed at dispatch.** Additional work goes to a new agent with a complete prompt, never as a mid-flight message to a running one. Agents correctly distrust in-flight scope changes; relying on them is both unreliable and trains the wrong instinct.

**C-7 — Verification re-runs the command.** An agent's report is a hypothesis. The Architect confirms a claim by executing the check, not by reading the summary. Applies with double force to an agent auditing its own output — the v13.34 loss audit is the counterexample.

**C-8 — Measure the quantity, not its proxy.** Replace the line-count cap with a byte budget plus a per-row ceiling, per the plan already written. Until then, detail goes to `docs/plan/` and the board stays short.

## 5. What this analysis does not claim

- Commit-authorship split, revert rate, and per-agent error counts were **not measured** — the agent tasked with quantifying them was terminated by a session usage limit before reporting. Marked `ölçülmedi`; not estimated.
- The 41 occurrences of `yanlış` are a keyword count, not a validated defect count. Some are prose. Treat it as an upper bound on recorded corrections, not a defect total.
- Whether the Implementer failures share a single tooling cause (e.g. a Windows/PowerShell environment producing the UTF-16 and CRLF artifacts) is plausible but **unverified**; two data points do not establish it.
